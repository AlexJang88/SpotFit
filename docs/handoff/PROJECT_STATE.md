## 2. 현재 범죄 타깃과 발표 설명

```text
R = 서울 자치구 5대범죄 발생건수 / 해당 자치구 0–17세 주민등록 아동인구 × 10,000
Y = ln(1 + R)
예측 원지수 = exp(예측 Y) - 1
```

- 이름: **아동 지역범죄 노출 모델**. 실제 아동 대상 범죄건수를 예측한 모델이 아니다.
- 발표 목적: 아동 거주 지역의 일반적인 범죄환경을 비교하는 보조지표.
- 자료 제약은 “프로젝트에서 확보한 자료로 자치구별 장기 아동 대상 범죄 시계열 구성 어려움”으로 표현한다.
  모든 공개 자료가 영구적으로 존재하지 않는다거나 확보가 절대 불가능하다고 단정하지 않는다.
- 아동범죄율/개인 피해 확률/직접적인 아동 위험을 측정한다고 말하면 안 된다.
- 범죄건수가 같아도 아동인구가 적으면 R이 높아진다. 분모 효과와 전체 범죄/거주인구의 불일치를 설명한다.
- 현재 성능은 이 대리지표와 순위를 맞힌 성능이지 실제 아동범죄 정답률이 아니다.

### 로그 변환을 설명한 내용

- 큰 R을 압축해 큰 값의 제곱오차가 학습을 과도하게 좌우하는 것을 완화하려는 목적.
- `log1p`는 0도 처리하고, 비율적인 차이에 상대적으로 초점을 맞추게 한다.
- R과 ln(1+R)의 실제 관측값 순위·5분위는 동일(단조변환).
- 로그 학습과 원척도 학습의 **예측 결과/예측 순위**는 다를 수 있다.
- 로그가 이상치/데이터 오류/분모 편향을 해결하지 않는다. 정규분포나 성능 향상을 보장하지 않는다.
- 현재 Y를 고정한 뒤 모델·Feature를 탐색했다. 로그 유무를 비교해서 로그가 우수하다고 확정한 근거는 현재 서비스 코드에 없다.
- 향후 비교한다면 동일 시간분할/입력정보/평가척도로 raw R vs log1p R를 평가해야 한다.
- `scripts/child_crime/build_borough_experiment_panel.py:56`에서 `np.log1p(panel.exposure)`로 생성.

발표 예시:

> 자치구별 장기간의 아동 대상 범죄자료 확보가 어려워, 예측 대상을 지역의 일반 범죄환경 비교로 조정했습니다.
> 5대범죄를 아동인구로 표준화한 보조지표이며 실제 아동 피해율은 아닙니다.
> 로그는 큰 값의 영향을 완화하기 위한 학습용 변환입니다. 로그 자체의 성능 이점은 별도 비교가 필요합니다.

공통 **12개 수치 Feature + 자치구 One-hot**:

```text
y, log_crime, log_child,
y_lag1, y_lag2, y_change,
log_crime_change, log_child_change,
log_crime_lag1, log_crime_lag2,
log_child_lag1, log_child_lag2
```

`log_crime/log_child`는 로그변환값. 중앙값 결측대체→표준화→Ridge, 자치구 범주 인코딩 포함.
1y: 핵심8/추세12 × alpha5종 × direct/delta = 20후보.
2y: 두 가용성 정책, 그룹 전진선택, alpha6종, direct/delta/components_direct/components_delta 비교.
2y `all_comparisons.csv`는 1056행. 개별 모든 Feature의 2^N 전수조합을 돌린 것이 아니다.
2y 최종 학습은 입력2015–2023→목표2017–2025, 총225개 구·연도쌍.

### 재생성 로직의 주의점

- 서버 시작 시 모델을 무조건 자동학습하는 구조가 아니다. API 서버는 시작하고 관리자 POST로 실행.
- 준비된 panel 및 priority inputs가 필요. 원자료 다운로드·ETL 전체 자동화 아님.
- force=true는 API 진입 가드를 건너뛰지만 runner는 존재파일 여부를 보고 학습한다.
  **모든 모델의 강제 재학습을 보장하는 구현이 아님.** 문서의 “강제 재학습” 표현을 그대로 믿지 않는다.
- 실험joblib만 남고 forecast/result가 없으면 runner가 재학습을 건너뛰어 exporter에서 실패할 수 있다.
- Lock은 worker/replica간 분산락이 아니다. 여러worker 배포 시 중복 학습 가능성 추가검토 필요.
- 학습성공 시 CSV캐시 초기화. 파일만 수동교체했으면 캐시/프로세스 재시작 여부 확인.

### 점수 표시

- Y가 낮은 순서 safety_rank1..25, 높은 순서 risk_rank1..25. 둘을 혼동하지 않는다.
- 5개 구씩 A=100,B=80,C=60,D=40,E=20. 낮은 노출일수록 높은 안전점수.
- 동률 처리 코드는 `rank(method='min')`; 향후 동률이 많으면 그룹 크기·연속순위 조건 재검토 필요.
- 여러 영역을 선택하면 프런트가 선택영역 동일비중 평균을 계산. 범죄모델 내부 Feature 가중치와 다름.
- UI: React19+TypeScript+Vite+Leaflet. HomePage, SafetyPanel, DetailCharts, API helpers.
- 사용자 요구 반영: 시/구/동레벨,25구·427동 검색(현재파일기준),호버레이블,지역점수 명칭,
  등급색범례,순위/금액목록,행정동에서자치구전용점수·추이숨김.
- 현재 UI의 `1년 후/2년 후`는 데이터기준 horizon. 2026년 화면에서 실제목표연도2026/2027을 명확히 보여줄 필요.
  일부 “2026.10 기준 예시” 문구가 남아 있으므로 정확한 현재일 기반표시로 과장하지 않는다.
