# 행정동 변경 감지·적용 자동화

## 표시 기준

화면의 `YYYY.MM 기준`은 오늘 날짜가 아니라 `backend/app/data/admin_boundary_registry.json`에 등록된 **실제 배포 경계의 효력 시작일**이다. 코드만 갱신되고 경계 도형이 준비되지 않은 상태는 적용 완료로 표시하지 않는다.

## 공식 소스와 수집 순서

1. 예정 감지: 서울시 법무행정서비스와 25개 자치구 입법예고·고시에서 `동명칭`, `구역획정`, `행정동`, `분동`, `통합`, `관할구역`을 매일 검색한다.
2. 시행 확정: 행정안전부 `주민등록주소코드 변경내역`의 최신 게시물과 직전 스냅샷을 비교한다.
3. 경계 확보: SGIS 행정구역경계 또는 검증된 경계 원본에서 새 행정동 도형을 확보한다.
4. 검증: 서울 25개 자치구, 코드 중복, 명칭, geometry validity, gap/overlap, 이전 코드와의 교차면적을 검사한다.
5. 적용: `valid_from` 날짜에 검색 목록·지도 GeoJSON·행정동 코드 매핑을 한 버전으로 배포하고 레지스트리를 갱신한다.
6. 알림: 예정 감지는 전체 공지, 확정 시 시행 예정 알림, 적용 완료 시 변경 완료 알림을 각각 한 번만 발행한다.

## 변경 상태

`detected → confirmed → scheduled → applied` 순서로만 전이한다. 공고 본문만 감지한 `detected` 상태는 자동 배포하지 않는다. 행안부 코드와 새 경계 도형 검증을 모두 통과해야 `applied`가 된다.

## 반드시 보존할 매핑

분동·통합·경계조정 시 과거 데이터를 새 코드로 덮어쓰지 않는다. `old_code`, `new_code`, `valid_from`, `valid_to`, `change_type`, `area_weight`, `population_weight`를 가진 교차표를 버전별로 보존한다. 모델 재학습 자료는 당시 행정동 버전과 함께 저장한다.

## 개인 알림 확장

로그인 기능이 추가되면 `user_id`, `admin_code`, `channel`, `enabled`를 저장하는 구독 테이블을 만들고, 변경의 구/동 코드와 일치하는 사용자에게만 발송한다. 현재 프로토타입은 로그인·푸시 토큰 저장소가 없으므로 모든 사용자에게 헤더 공지로 표시한다.
