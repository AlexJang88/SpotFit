# 월세 전환율 모델 — 행정동 단위 서비스 구현 안내

백엔드·프론트엔드 담당자가 월세 모델을 **행정동 단위 화면**으로 구현할 때 참고하는 문서입니다.

- 학습 코드: `ml/training/RentConversionFinal.py`
- 서버용 모델 파일: `models/recommender/v1/apart_wolse_final/model_bundle.joblib`
  - 서버가 시작할 때 `backend/app/services/property_model_bootstrap.py`가 자동으로 준비합니다.
- 요약 정보: 같은 폴더의 `summary.json`

---

## 1. 한 줄 요약

모델은 **계약(집) 하나하나의 전환율**을 예측합니다. 행정동 화면은 다음 순서로 만듭니다.

1. 그 동의 건물마다 예측합니다.
2. 예측 결과를 동 단위로 모아 **중앙값과 범위**를 보여줍니다.

사용자는 **보증금 또는 월세 중 하나만** 입력하면 됩니다.

---

## 2. 모델이 하는 일

### 전환율이란

```
전환율 r = 12 × 월세 ÷ (기준 전세가 J − 보증금)
```

- **기준 전세가 J**
  - 같은 건물, 같은 면적대(5㎡ 단위)의 직전 12개월 전세 실거래 ㎡당 중앙값에 면적을 곱한 값입니다.
  - 전세 거래가 2건 이상일 때만 만듭니다. 동 평균 같은 대체값은 쓰지 않습니다.
- **동 앵커 an_d**
  - 직전 12개월 그 행정동의 전환율 중앙값입니다.
  - 동 계약이 30건 미만이면 자치구 값을, 그것도 30건 미만이면 서울 값을 씁니다.
- **모델 출력**
  - 동 앵커에서 이 집이 얼마나 벗어나는지를 예측합니다.
  - 최종 전환율: `r̂ = an_d + 모델 출력`. 결과는 0.5%~15% 범위로 자릅니다.

### 양방향 계산

| 사용자 입력 | 계산식 | 조건 |
|---|---|---|
| 보증금 D | 월세 = r̂ × (J − D) ÷ 12 | D ≤ J × 0.8 |
| 월세 R | 보증금 = J − 12 × R ÷ r̂ | 결과가 0보다 커야 함 |

금액 단위는 모두 **만원**이고, 면적은 **임대면적(㎡)**입니다.

### 성능 (2024년까지 학습 → 2025-01~2026-09 시험, 104,355건, 계약 단위)

| 방향 | 평균 오차 | 오차율 중앙 | R² |
|---|---|---|---|
| 보증금 입력 → 월세 | 28.0만원 | 12.9% | 0.856 |
| 월세 입력 → 보증금 | 7,062만원 | 31.0% | 0.715 |

- 전환율 자체의 오차는 중앙 0.65%p이고, 편향은 +0.02%p입니다.
- **보증금 방향은 오차가 큽니다.** 화면에서 범위를 함께 보여주고, 안내 문구를 다는 것을 권장합니다.
- 행정동 단위로 모았을 때는 오차가 더 큽니다(6장 참고).
  - 월세: 오차율 중앙 14.4% (거래량 가중)
  - 보증금: 37.0%, 20평 미만을 빼면 23~26%

## 3. 모델 파일 구성

```python
import joblib
b = joblib.load("models/recommender/v1/apart_wolse_final/model_bundle.joblib")
```

| 키 | 내용 |
|---|---|
| `model` | scikit-learn `HistGradientBoostingRegressor`. 출력은 전환율 − 동 앵커입니다. |
| `features` | 모델 입력 항목 28개. **이 순서대로** 넣어야 합니다. |
| `rate_clip` | `[0.005, 0.15]` |
| `deposit_to_jeonse_max` | `0.8` |
| `trained_until` | 학습 데이터 마지막 날짜 (2026-09-30) |
| `stats_basis` | 표의 기준 시점 (2026-09 말) |
| `test_before_refit` | 2장의 시험 성능 |
| `tables` | 서비스 계산용 표 (아래) |

### `tables`

| 표 | 키 | 주요 열 | 의미 |
|---|---|---|---|
| `dong` | `동` | `dong_rs`, `dong_ds`, `dong_cnt`, `seoul_rs`, `gu`, `gu_rs`, `gu_ds` | 직전 12개월 동·자치구·서울 월세 수준 (㎡당 월세, ㎡당 보증금, 계약 수) |
| `anchor` | `동` | `an_d`, `an_s`, `an_lvl` | 동 앵커 전환율, 서울 전환율, 앵커 수준(dong/gu/seoul) |
| `jeonse` | `bk` | `j_b`, `j_n` | 같은 건물·면적대 전세 ㎡당 중앙값과 건수 (2건 이상만) |
| `building` | `bk` | `b_rs`, `b_ds`, `b_cnt`, `b_R`, `b_D` | 같은 건물·면적대 직전 24개월 월세 이력 |
| `kapt` | `key` | `ka_*` 9개 | K-apt 단지 정보 (세대수, 동수, 최고층, 주차, 임대 비율, 승강기, 난방·복도·분양 형태) |
| `default_deposit` | `동`, `abin` | `def_D`, `def_med`, `def_n` | 화면 초기값용 보증금 (동·10㎡ 구간별, 계약 10건 이상) |
| `gu_names` | — | — | 자치구 번호 → 자치구 이름 |
| `building_info` | `bk` | `동`, `자치구`, `법정동`, `지번`, `F`, `Y0`, `A`, `info_n`, `band` | 건물·면적대별 행정동과 주소(가장 최근 거래 기준), 층·건축년도·면적 중앙값, 거래 수, 면적대 (월세+전세 실거래) |
| `bands` | — | — | 면적대 번호 → 이름 (1: 20평 미만, 2: 20평대, 3: 30평대, 4: 40평 이상) |

**키 만드는 법**
- `동`: 상권분석 서비스의 **행정동 코드 8자리** (예: `11110530`)
- `bk`: `"{법정동} {지번} {round(면적/5)}"` (예: `"역삼동 123-4 17"`, 17 = 85㎡ ÷ 5)
- `key`: `"{자치구}|{법정동}|{지번 본번 숫자}"` (예: `"강남구|역삼동|123"`)
- `abin`: `min(면적 // 10, 12)`

### 모델 입력 항목 28개

```
A, F, age                                    면적(㎡), 층, 연식(계약 연도 − 건축년도)
dong_rs, dong_ds, dong_cnt, gu_rs, seoul_rs  ← tables.dong
b_rs, b_ds, b_cnt, b_R, b_D                  ← tables.building (없으면 NaN 가능)
ka_hh … ka_sale (9개)                        ← tables.kapt (없으면 NaN 가능)
J, logJ, j_src, j_n                          ← tables.jeonse (J = j_b × A, j_src = 2)
an_s, an_d                                   ← tables.anchor
```

- 모델이 빈 값(NaN)을 직접 처리하므로 건물 이력과 K-apt는 비어 있어도 됩니다.
- **J(기준 전세가)와 앵커가 없으면 예측할 수 없습니다.**

### 예측 함수

기준 함수는 모두 `RentConversionFinal.py` 안에 있습니다.

| 함수 | 용도 |
|---|---|
| `predict(bundle, rows, deposit=…)` 또는 `predict(bundle, rows, rent=…)` | 집 한 채 단위 예측 |
| `dong_service(bundle, dong, band, year, deposit=…)` 또는 `dong_service(bundle, dong, band, year, rent=…)` | 행정동·면적대 단위 예측 (4장 방식) |

- 이 파일은 import하는 순간 학습이 돌아갑니다. 그래서 함수는 **복사해서** 백엔드 서비스 모듈로 옮겨야 합니다.
- 함께 옮겨야 하는 것: `features()`, `kkey()`, `wquant()` 함수와 `LO, HI, DJ_MAX, MIN_BLD` 상수
- `dong_service` 결과 예시 (실제 출력, 숫자는 반올림):

```python
# 보증금 입력 → 월세 (거래량 가중)
{'dong': 11350700, 'band': '20평대', 'output': 'rent', 'unit': '만원', 'dong_rate': 0.0373, 'dong_rate_level': 'dong',
 'buildings_used': 3, 'weighted': True, 'result': {'median': 35.4, 'p25': 35.4, 'p75': 61.7}}
# 월세 입력 → 보증금 (가중 없음)
{'dong': 11350700, 'band': '20평대', 'output': 'deposit', 'unit': '만원', 'dong_rate': 0.0373, 'dong_rate_level': 'dong',

# 20평 미만 보증금 → 결과 없음
```

- 예측 가능한 건물이 `MIN_BLD`(3곳) 미만일 때
- 20평 미만에서 월세로 보증금을 물을 때

## 4. 행정동 단위 서비스 구현 방법

### 화면 흐름

1. 사용자가 **행정동**을 선택합니다. 지도 클릭 또는 목록에서 고릅니다.
2. **면적대**를 선택합니다. 예: 10평대, 20평대, 30평대.
3. **보증금 또는 월세** 중 하나를 입력합니다.
   - 초깃값은 `default_deposit`의 그 동·면적대 `def_med`(보증금 중앙값)를 쓰면 됩니다.
   - **20평 미만을 고르면 월세 입력(→ 보증금 예측)을 막습니다.** 예: 입력칸 비활성화 + "이 면적대는 보증금 예측이 부정확해 제공하지 않습니다"
4. 결과를 보여줍니다.
   > 보증금 1억 → 예상 월세 **중앙 120만원** (보통 95~150만원)
   > 계산에 쓴 건물 18곳 · 이 동 전환율 4.7%

### 서버 계산 순서

```
입력: 동 코드, 면적대(㎡ 범위), 보증금 D 또는 월세 R

0. 월세 R 입력 + 20평 미만이면 바로 "제공하지 않음"을 돌려줍니다.
1. 후보 건물 고르기
   - tables.building_info에서 동 == 선택한 동, band == 선택한 면적대인 건물을 고릅니다.
   - 그중 bk가 tables.jeonse에 있는 것만 남깁니다.
     (bk가 없는 건물은 기준 전세가가 없어 예측할 수 없습니다.)
2. 건물마다 입력 행을 만듭니다.
   - building_info의 자치구, 법정동, 지번, 동, A, F, Y0를 쓰고, year = 올해
3. predict(bundle, 행들, deposit=D) 또는 predict(bundle, 행들, rent=R)
4. 예측 불가(NaN) 건물은 뺍니다.
   - 보증금 방향: D > J × 0.8 인 건물
5. 동 단위로 요약합니다.
   - 중앙값, 25%·75% 값, 건물 수, 동 앵커 an_d, 앵커 수준 an_lvl
   - 월세 결과(보증금 입력): 건물별 직전 24개월 월세 계약 수(b_cnt)로 가중한 중앙값·25%·75%
     · 이유: 실제 거래가 많은 건물을 더 반영합니다. 시험 오차율 중앙 17.8% → 14.4%
     · 가중할 건물이 하나도 없으면(b_cnt가 모두 0) 가중 없이 계산합니다.
   - 보증금 결과(월세 입력): 가중 없는 중앙값·25%·75% (가중해도 나아지지 않았습니다)
6. 건물이 3곳 미만이면 "거래가 적어 예측하기 어렵습니다"로 표시합니다.
   (시험에서는 건물 수가 적다고 오차가 커지지 않았습니다. 3곳은 범위를 보여주기 위한 최소 기준입니다. 6장 참고.)
```

- **같은 면적대에서는 입력 금액이 같아도 건물마다 전세가가 달라 결과가 다릅니다.** 동 결과는 "이 동에서 이 조건이면 보통 이 정도"라는 뜻입니다.
- 건물별 목록(건물명, 예상 금액)을 함께 보여주면 사용자가 차이를 이해하기 쉽습니다.
- **가중의 주의점:** 거래가 아주 많은 건물 한 곳이 있으면 결과가 그 건물 쪽으로 쏠립니다.
  - 위 예시처럼 건물이 3곳뿐이면 중앙값과 25% 값이 같게 나오기도 합니다.
  - 그래서 범위(25~75%)와 건물 수를 함께 보여주는 것을 권장합니다.

### 응답 예시 (제안)

```json
{
  "dong_code": "11680640",
  "area_band": "20평대 (66~99㎡)",
  "input": {"deposit": 10000},
  "result": {"rent_median": 120, "rent_p25": 95, "rent_p75": 150, "unit": "만원"},
  "buildings_used": 18,
  "dong_rate": 0.047,
  "dong_rate_level": "dong",
  "basis": "2026-09 말 실거래 기준",
  "weighted": true,
  "note": "보증금 입력 → 월세: 행정동 단위 오차율 중앙 약 14%"
}
```

## 6. 행정동 단위 성능 (시험 결과)

`RentConversionFinal.py`에서 4장 방식 그대로 시험했습니다. 결과 파일은 `data/processed/output/월세계약_전환율모델_행정동시험.csv`입니다.

**시험 방법**
- 2024년까지 학습한 모델로 2025-01~2026-09를 시험했습니다.
- 분기마다 그 시점의 표만 사용했습니다.
- 묶음 = (행정동, 면적대, 분기), 실제 계약 5건 이상. 묶음은 4,583개, 계약은 103,975건입니다.
- 입력: 묶음 실제 계약의 보증금(또는 월세) 중앙값
- 정답: 묶음 실제 계약의 월세(또는 보증금) 중앙값

**결과 (건물 3곳 이상인 묶음)**

| 방법 | 월세 오차율 중앙 | 월세 MAE | 보증금 오차율 중앙 | 보증금 MAE |
|---|---|---|---|---|
| **서비스 방식** (동 안 건물 예측의 중앙값) | 17.8% | 36.0만원 | 37.0% | 8,835만원 |
| 서비스 방식 + 건물 거래량 가중 | 14.4% | 33.9만원 | 36.1% | 9,111만원 |
| 동 앵커만 (전환율 = 동 중앙값) | 19.4% | 38.6만원 | 39.5% | 9,363만원 |
| (참고) 실제 계약마다 예측한 뒤 중앙값 | 8.1% | 17.7만원 | 19.7% | 4,609만원 |

**해석**
- 서비스 방식은 동 앵커만 쓰는 것보다 낫습니다.
- 하지만 실제 계약마다 예측한 값(8.1%)보다는 크게 나쁩니다.
  - 차이의 원인은 모델 오차보다 **"그 동에서 실제로 어떤 건물에서 거래가 일어나는가"**입니다.
  - 서비스 방식은 동 안 건물을 모두 같은 비중으로 셉니다. 실제 거래는 일부 건물에 몰립니다.
- 건물 거래량(직전 24개월 월세 계약 수)으로 가중하면 월세 쪽이 17.8% → 14.4%로 좋아집니다. 보증금 쪽은 오차율은 비슷하고 MAE는 오히려 나빠집니다.
  - **그래서 `dong_service()`는 월세 결과에만 가중을 씁니다.**
- 건물 수별 월세 오차율 중앙: 1~2곳 13.8%, 3~5곳 15.4%, 6~10곳 18.6%, 11곳 이상 19.1%
  - 건물이 많은 동일수록 건물 간 가격 차이가 커서, 중앙값 하나로 요약하기 어렵습니다.
  - 그래서 화면에 **25~75% 범위를 꼭 함께 보여주는 것**을 권장합니다.
- 면적대별 오차율 중앙 (건물 3곳 이상)

  | 면적대 | 월세 | 보증금 |
